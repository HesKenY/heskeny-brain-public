What we're building

A field-intelligence platform for construction crews, with an AI maintenance layer that keeps it running and learning.

CHERP — multi-tenant construction crew PWA on Supabase, maintained by an autonomous agent stack on a local 4070, evidence-gated and offline-capable.

Crews use CHERP on their phones for daily logs, JSAs, timecards, calculators, and trade-specific reference. Office staff see everything in real time without installing anything. The AI behind it keeps the code shipping safely.

7 trade variants on cherp.live + offline-capable solo PWAs. Supabase RLS-bound. KenAI on Ollama drives migrations + bug-fixing via the KenOS v1.2 controller. Cross-agent claim verifier gates every shipped change.

Where we're heading
  1. 1

    Get CHERP into more crews

    CHERP solo→company funnel + per-trade variants

    Each trade gets its own free phone app on the App Store. Crews try it solo, like it, and pay to connect their whole company.

    7 trade-named PWAs (Pipe Trades / Electricians / HVAC / Fire Sprinkler / Carpentry / Concrete / Safety / General) on cherp.live + a federation-v0 device-code flow so a worker's solo app attaches to a company instance. Single Supabase, runtime CHERP_TRADE flag.

  2. 2

    Sell company instances

    Per-company Supabase isolation + SharePoint sync

    When a company signs up, they get their own private CHERP space. Their existing Microsoft Office files and SharePoint sites all sync automatically.

    Tier A architecture: single Supabase project, RLS isolation per company_id; Wave-1 + Wave-1b SharePoint daily-folder routing live for Debe Corp as the first paid instance.

  3. 3

    AI that builds + fixes itself

    KenOS controller + wolverine self-write loop

    Most of CHERP's code now gets written and fixed by AI running on a single GPU in Ken's office. Customers get faster releases without us hiring a full dev team.

    KenOS v1.2 dispatches goals to the kenai-fullstack/wolverine agents. Wolverine has gated self-write to its own controller source. Cross-agent claim verifier checks every claimed change.

  4. 4

    Pokemon training — proof the AI learns live

    kenai-trainer: autonomous Pokémon Crystal completion as the Play→Break→Fix loop

    We're teaching one of our AI models to play and beat Pokémon Crystal — completely on its own. It's not for fun. It's the same loop we use to teach the AI to fix CHERP bugs: try something, see what happened, learn, try again. If the AI can finish Pokémon, it can finish a feature.

    kenai-trainer:latest drives mGBA via xdotool, produces lesson seeds (84 banked), separate corpus from kenai-v5 dev corpus per the no-dilution rule. Same loop pattern feeds the bug-hunter pipeline (find vuln → patch → seed) and CHERP migrations.

  5. 5

    Revenue: bug bounties + paid CHERP instances

    Phase-1 bounty packets (Nexon/Epic/Ubisoft/Google) + paid Debe Corp + future tier-A companies

    Two revenue streams while CHERP grows: (1) we find security bugs in big companies' software and get paid bounties; (2) construction companies pay monthly for CHERP. The bounties also train our AI to find bugs in CHERP itself.

    $10K floor / $120K ceiling on the four drafted Phase-1 packets. Debe Corp is the first paid CHERP instance; Heskeny-Brain investor portal carries the public evidence.

How it connects

The full stack at a glance

Field crews and office staff use the CHERP app. Everything they enter goes into the cloud database and (for Debe Corp) into SharePoint at the same time. The AI agents on Ken's local GPU build and fix the code, and the BRAIN keeps every action logged so we can prove what happened.

Static PWA → Supabase (REST + RLS) + Netlify functions → Microsoft Graph (SharePoint). Local KenAI on Ollama via litellm Anthropic-compat proxy → KenOS v1.2 controller → workspace-jailed tools. BRAIN holds canonical state (master.log JSONL + handoffs + evidence).
